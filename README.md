# Occlusion-Robust Face Identification Using a Pretrained ArcFace Model

CSE 4112 Machine Learning Laboratory project (KUET) — closed-set face identification
of 30 enrolled people under masks, sunglasses, scarves, caps, and combined occlusions,
using a pretrained ArcFace (`buffalo_l`, iResNet50) embedding model and a RetinaFace
detector, with no training required to reach ~99.5% test accuracy and a partial
backbone fine-tune reaching 100%.

Full write-up: [`docs/final_report.tex`](docs/final_report.tex) / `docs/final_report.pdf`.
Design docs: [`docs/training_plan.md`](docs/training_plan.md), [`docs/preprocessing_plan.md`](docs/preprocessing_plan.md).

## Results at a glance

| Experiment | Description | Test top-1 |
|---|---|---|
| E0 | Pretrained embedding, nearest-centroid, **no training** | 99.50% |
| E1 | Trained 30-way head, clean faces only | 70.34% |
| E2 | Trained 30-way head, all 8 occlusion conditions | 96.29% |
| E3 | Partial backbone fine-tune (last 15%), all conditions | **100.00%** |

30 identities, 6,000 raw images, 5,988 successfully preprocessed (99.8% detection rate),
split 3,546 / 1,444 / 998 (train/val/test) with group-aware deduplication and a hard
guarantee that every identity appears in all three splits.

## Setup

Python 3.10+. Two environments are used in this project:

- **Remote GPU box** (training: preprocessing, splitting, embedding, E0–E3) — 2x RTX 3090.
- **Local laptop** (deployment: the live demo) — CPU only, no GPU required.

```bash
pip install insightface onnxruntime-gpu opencv-python-headless numpy pandas scikit-learn tqdm
# training only (E3 / onnx2torch fine-tuning):
pip install torch torchvision onnx2torch
# demo only:
pip install flask gevent cryptography
```

The two ONNX weight files actually used (`det_10g.onnx` for detection, `w600k_r50.onnx`
for recognition — ~185 MB total) are kept locally at `models/buffalo_l/` so the repo is
self-contained and doesn't depend on a fresh download every time. `scripts/common.py`'s
`default_model_root()` / `default_rec_model_path()` resolve to this folder automatically
and every script (`01`, `03`, `06`, `08`, `09`, `10`) uses them; if `models/buffalo_l/`
is missing (e.g. a fresh clone), they fall back to `insightface`'s own auto-download
cache at `~/.insightface/models/`. `models/` is gitignored (`*.onnx`) since the weights
are large binaries and freely re-downloadable — copy them from `~/.insightface/models/buffalo_l/`
after first running any insightface script once, or just let the fallback handle it.

> **onnxruntime-gpu note:** installing plain `onnxruntime` after `onnxruntime-gpu` silently
> overwrites it with a CPU-only build. Install `onnxruntime-gpu` last, with `--no-deps`, and
> pin a version matching your installed CUDA runtime (e.g. `onnxruntime-gpu==1.20.2` for CUDA 12.4).

## Running the pipeline (in order)

All scripts are run from the repository root and read/write relative to it unless a
`--*-dir` / `--*-path` flag says otherwise. Run `python scripts/<script>.py --help` for
the full flag list of each.

```bash
# 1. Detect, align, crop every image in processed_data/ -> crops/ + metadata/preprocess_log.csv
python scripts/01_preprocess.py

# 2. Build the group-aware train/val/test split -> metadata/manifest.csv
python scripts/02_split.py

# 3. Extract ArcFace embeddings for every crop -> runs/embeddings.npz
python scripts/03_embed.py

# 4. E0 — nearest-centroid probe (no training)
python scripts/04_e0_probe.py

# 5. E1 / E2 — trained ArcFace head
python scripts/05_train_head.py --mode normal   # E1: clean-only
python scripts/05_train_head.py --mode mixed    # E2: all occlusions

# 6. E3 — partial backbone fine-tune (needs a CUDA GPU; verifies onnx2torch fidelity first)
python scripts/06_e3_finetune.py

# 7. Build the deployment gallery (centroids from ALL data) + calibrate the UNKNOWN threshold
python scripts/07_build_gallery.py

# 8. Try it on a single image
python scripts/08_demo.py --gallery runs/gallery.npz --image path/to/photo.jpg
```

Each script is idempotent and re-reads the previous step's output — re-running an
earlier step (e.g. after adding data) does **not** automatically re-run later steps.

## Running the live phone demo

The demo is a Flask server on your laptop; your phone connects to it over the same
Wi-Fi network as a browser page and uses its camera.

```bash
python scripts/09_server.py --gallery runs/gallery.npz [--show-names] [--port 5000]
```

The server prints your laptop's LAN IP and starts an HTTPS server (self-signed
certificate, auto-generated once under `runs/certs/` and reused on restart) using
`gevent` — **not** Flask's built-in dev server, which was found to hang indefinitely
during the TLS handshake with real mobile browsers.

On your phone (same Wi-Fi network):

1. Open `https://<laptop-LAN-IP>:5000` (shown in the server's startup output).
2. Accept the "connection is not private" / self-signed-certificate warning
   (Advanced → Proceed / Visit site) — this is expected and only needs doing once
   per phone, since the certificate persists across server restarts.
3. Tap **Start** and grant the camera permission when prompted.
4. If the picture looks blurry or has an unusually wide/"fisheye" field of view,
   use the camera dropdown to pick a different physical lens (many phones default
   to an ultra-wide rear lens), or tap **Switch Camera** to flip front/back.

`getUserMedia` (camera access) only works in a **secure context** — `https://` or
`localhost` — which is why this demo requires HTTPS even on a local network; a plain
`http://<ip>` page will not even prompt for camera permission on a phone browser.

Flags:

| Flag | Purpose |
|---|---|
| `--gallery` | path to a `gallery.npz` built by `07_build_gallery.py` (default: `runs/gallery.npz`) |
| `--names` | path to `metadata/person_id_mapping.txt`, used only with `--show-names` |
| `--show-names` | display real member/person names instead of raw `p##` IDs |
| `--port` | server port (default `5000`) |
| `--threshold` | override the calibrated UNKNOWN-rejection threshold |

## Key design notes (see `docs/training_plan.md` for full detail)

- **Identical alignment everywhere.** `scripts/common.py`'s `align_crop()` is used
  by preprocessing, embedding, evaluation, and the live demo. Never reimplement
  alignment separately — a mismatch here is the most common cause of "works in
  testing, fails in the demo."
- **The dataset is frozen.** `processed_data/` is treated as a fixed input as of
  the start of preprocessing; no images are added, removed, or relabelled after
  that point. Exact-duplicate images (429 of them, by MD5) are deliberately **not**
  deduplicated for the split — each counts as an independent image, and the
  resulting ~8% test/train MD5 overlap is measured and reported rather than hidden.
- **Every identity appears in all three splits** (hard assertion in `02_split.py`);
  per-occlusion coverage per split is best-effort only.
- **Embeddings are NOT pre-normalized** by `insightface`'s `get_feat()`. Always
  L2-normalize before computing cosine similarity or a threshold — this was the
  cause of a real bug during development (see `docs/final_report.pdf`, Results).
- **Gallery over trained head for deployment.** The live demo uses per-identity
  mean-embedding centroids (rebuilt from all data) rather than a fixed classifier
  head, because it scored at least as well (E0/E3) and lets a new example be added
  to a participant's centroid without retraining.

## Privacy / consent

Every participant signed a consent form before being photographed. Raw images and
the participant-identity mapping (`metadata/person_id_mapping.txt`) are restricted
to the six project members and are not published outside the group. See
`docs/consent.pdf` for the form used.
